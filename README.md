# V9 — мгновенная оценка ежедневных заданий

Изменения:
- Нет статуса ожидания для **новых** ежедневных ответов.
- Сервер сразу сравнивает ответ с проверенными эталонами, с учётом нормализации регистра, пробелов и знаков препинания.
- Точное совпадение при подтверждении: +10. Исправление ошибочного варианта на эталон: +15. «Исправление» уже корректного варианта: +10. Иные ответы: 0 и статус `rejected`.
- Проверка текстовая, **не смысловая**: хороший синоним, отсутствующий в эталонах, может быть отклонён. Это не оценка знания языка и не экспертное заключение.
- Не менялись роли, классы, журнал корректировок баллов, структура БД и Telegram-бот за исключением сообщений обратной связи.

## Обновление V8 → V9

1. Сделать резервную копию PostgreSQL и сохранить `.env`.
2. Распаковать V9 вместо файлов приложения, сохранить собственный `.env`.
3. В папке с `docker-compose.yml`:

```powershell
docker compose --profile telegram --profile voice build api bot
docker compose --profile telegram --profile voice up -d
docker compose exec api python -m scripts.migrate_instant_v9
```

**Не выполнять** `docker compose down -v`.

Миграция обрабатывает только ранее ожидавшие (`pending`) ответы, не меняя ручные корректировки модератора. Её можно повторить без повторных начислений.

## Ограничения

- Убедитесь, что `AUTO_GRADE_CORPUS_REFERENCES=true` задан в `.env`, если нужно автопроверять импортированные эталоны Hugging Face. При `false` совпадения с непроверенными корпусными эталонами не будут засчитываться.
- Если перевод отсутствует среди эталонов, он сразу получает 0 баллов. Для корректной работы с синонимами нужно дополнять проверенные эталоны. Не следует называть такие ответы объективно неправильными.
- Роль модератора и существующие API модерации сохранены для обратной совместимости, но новые ежедневные ответы не попадают в очередь `pending`.
