## О проекте

**«Башҡорт теле»** — образовательный проект в формате «башкирского Duolingo», разработанный по задаче хакатона «Башкирская языковая школа». Пользователи получают короткие ежедневные задания: видят фрагмент на башкирском языке и предложенный перевод, после чего подтверждают его или предлагают исправление.

Проект объединяет практику языка, элементы геймификации, словарь с озвучкой, рейтинги и инструменты преподавателя. Ответы и источники переводов хранятся в PostgreSQL и доступны через документированный REST API.

> **Статус:** работающий прототип (V9). Автоматическая проверка сверяет текст с известными эталонами; она не гарантирует смысловую правильность перевода и не распознаёт все синонимы.

## Возможности

| Раздел | Что умеет |
|---|---|
| 📅 **Ежедневные задания** | Подтверждение и исправление башкирских переводов, результат без ожидания модерации |
| 📖 **Словарь** | Поиск по башкирским словам и переводам в выбранной языковой паре |
| 🔊 **Озвучка** | Башкирская речь через отдельный TTS-сервис; перевод — через доступные голоса браузера |
| 🏆 **Геймификация** | Баллы, уровни, достижения и рейтинги пользователей, классов и школ |
| 🔁 **Повторение** | Просмотр ранее выполненных заданий для закрепления материала |
| 🎓 **Учитель** | Создание своих классов, управление составом и просмотр прогресса учеников |
| 🛡️ **Модератор** | Проверка переводов, ручное начисление/списание баллов с журналом изменений |
| ⚙️ **Администратор** | Назначение ролей, школ и владельцев классов |
| 🤖 **Telegram-бот** | Получение и выполнение заданий, выбор языка, просмотр профиля |
| 🔌 **REST API** | Доступ к фрагментам и переводам, CSV-экспорт, Swagger / OpenAPI |

### Правила оценки в V9

- **+10 баллов** — правильное подтверждение по известному эталону.
- **+15 баллов** — исправление ошибочного предложенного варианта на эталонный.
- **+10 баллов** — правильная альтернатива, когда предложенный вариант уже был верным.
- **0 баллов** — ответ, не совпавший с известными эталонами.

Сравнение выполняется после нормализации регистра, пробелов и пунктуации. **Ответ без совпадения с эталоном не обязательно лингвистически ошибочен:** в корпусе может не быть допустимого синонима. Для более строгого режима проверки можно установить `AUTO_GRADE_CORPUS_REFERENCES=false` и использовать только специально подтверждённые эталоны.

## Технологии и архитектура

```text
                  ┌────────────────────┐
                  │  Веб-интерфейс     │
                  │  HTML / CSS / JS   │
                  └─────────┬──────────┘
                            │
┌──────────────────┐        ▼
│ Telegram-бот     │ ───► FastAPI ◄──► PostgreSQL
│ aiogram          │       │
└──────────────────┘       └──► TTS-сервис (опционально)
                                  │
                           facebook/mms-tts-bak
```

- **Backend:** Python, FastAPI, SQLAlchemy, Pydantic.
- **База данных:** PostgreSQL 16.
- **Frontend:** HTML, CSS, JavaScript.
- **Telegram:** aiogram.
- **Озвучка:** отдельный Docker-сервис для башкирского TTS; Web Speech API для языков перевода.
- **Запуск:** Docker Compose, опциональные профили `telegram` и `voice`.

## Быстрый старт

Необходимы **Git**, **Docker Desktop** с запущенным Docker Engine и подключение к Интернету для импорта корпуса (а также первой загрузки TTS-модели).

### 1. Склонируйте проект

```powershell
git clone https://github.com/danilmukhyanov-prog/bashkort-tele.git
cd bashkort-tele
```

### 2. Настройте переменные окружения

```powershell
Copy-Item .env.example .env
```

В локальном `.env` измените как минимум:

```dotenv
SECRET_KEY=укажите_длинный_случайный_секрет
ADMIN_EMAIL=admin@example.org
ADMIN_PASSWORD=укажите_надёжный_пароль
POSTGRES_PASSWORD=укажите_пароль_базы
DATABASE_URL=postgresql+psycopg://school:ТОТ_ЖЕ_ПАРОЛЬ@db:5432/school
AUTO_GRADE_CORPUS_REFERENCES=true
BOT_TOKEN=
```

`POSTGRES_PASSWORD` и пароль в `DATABASE_URL` должны совпадать. Для нового развёртывания задайте значения **до первого запуска БД**. При смене пароля уже существующей базы простого редактирования `.env` недостаточно.

**Никогда не добавляйте `.env` в Git.** Для публичного репозитория используйте только `.env.example` без секретов.

### 3. Запустите сайт и PostgreSQL

```powershell
docker compose up -d --build
```

После запуска откройте:

- **Сайт:** http://localhost:8000
- **Swagger UI:** http://localhost:8000/docs
- **Проверка сервера:** http://localhost:8000/health

### 4. Импортируйте задания

Пустая база **не содержит ежедневных упражнений** — их нужно импортировать отдельно:

```powershell
docker compose exec api python -m scripts.import_hf --dataset phrasebooks --limit 1000
```

Загрузка идёт из открытого корпуса [bashkorttele/trilingual-parallel-phrasebooks-bgpu](https://huggingface.co/datasets/bashkorttele/trilingual-parallel-phrasebooks-bgpu).

Проверьте, что появились переводы для языковой пары `ba-ru`:

```powershell
docker compose exec db psql -U school -d school -c "SELECT lang_pair, COUNT(*) FROM suggestions GROUP BY lang_pair;"
```

### 5. Запустите Telegram-бота (по желанию)

Создайте бота через [@BotFather](https://t.me/BotFather), задайте `BOT_TOKEN` в локальном `.env` и выполните:

```powershell
docker compose --profile telegram up -d --build
```

Команды бота: `/start`, `/daily`, `/language`, `/profile`, `/cancel`. Учётные записи сайта и Telegram создаются отдельно и автоматически **не объединяются**.

### 6. Включите башкирскую озвучку (по желанию)

```powershell
docker compose --profile telegram --profile voice up -d --build
```

При первом синтезе модель загружается из Hugging Face. Это может потребовать дополнительных ресурсов и времени. Диагностика:

```powershell
docker compose --profile voice ps
docker compose --profile voice logs --tail=100 tts
```

Модель [facebook/mms-tts-bak](https://huggingface.co/facebook/mms-tts-bak) распространяется по лицензии **CC BY-NC 4.0** (некоммерческое использование). Учитывайте лицензию при распространении и развёртывании продукта.

| Прогресс учеников своих классов | — | ✅ | — | ✅ |
| Проверка переводов | — | — | ✅ | ✅ |
| Корректировки баллов | — | — | ✅ | ✅ |
| Назначение ролей | — | — | — | ✅ |

Ролевая проверка выполняется **в API**, а не только через скрытие интерфейсных кнопок. Ручная корректировка баллов ограничена диапазоном от −100 до +100 за операцию (кроме 0), требует причины, не допускает отрицательного баланса и фиксируется в журнале.

## API и выгрузка данных

Документация автоматически доступна по адресу `/docs`. Основные методы:

| Метод | Маршрут | Назначение |
|---|---|---|
| `POST` | `/v1/auth/register` | Регистрация |
| `POST` | `/v1/auth/login` | Авторизация |
| `GET` | `/v1/daily` | Ежедневное задание |
| `POST` | `/v1/answers` | Отправка и автопроверка ответа |
| `GET` | `/v1/dictionary` | Словарь |
| `GET` | `/v1/leaderboard` | Рейтинг |
| `GET` | `/v1/me/history` | История ответов |
| `GET` | `/v1/practice/review` | Повторение |
| `GET` | `/v1/translations/export.csv` | Экспорт переводов |
| `GET/POST` | `/v1/teacher/classes` | Классы учителя |
| `POST` | `/v1/moderator/users/{user_id}/points` | Изменение баллов |
| `POST` | `/v1/admin/users/{user_id}/role` | Назначение роли |

Для защищённых запросов используется `Authorization: Bearer <JWT>`.

## Обновление существующей установки

**Не удаляйте том PostgreSQL.** Команда `docker compose down -v` удаляет тома и может привести к потере пользователей, переводов и истории.

Для обновления уже работающей версии до V9:

1. Сохраните `.env` и сделайте резервную копию базы.
2. При переходе с более ранних версий выполните миграции согласно [README_V8.md](README_V8.md) и [README_V9.md](README_V9.md); особенно важна миграция ролей V8 **перед** запуском обновлённого API.
3. Соберите и запустите новую версию:

```powershell
docker compose --profile telegram --profile voice up -d --build
```

4. Если обновляете **V8 → V9**, обработайте старые ожидавшие ответы:

```powershell
docker compose exec api python -m scripts.migrate_instant_v9
```

Миграции старых версий **не следует запускать вслепую** на рабочей базе: сначала проверьте текущую версию и создайте резервную копию.

## Тестирование и диагностика

```powershell
# Логи серверной части
docker compose logs --tail=100 api

# Логи бота
docker compose --profile telegram logs --tail=100 bot

# Тесты (если pytest установлен в выбранном окружении)
python -m pytest -q
```

Автоматические тесты покрывают отдельные сценарии оценки, ролей и данных. Они **не заменяют** интеграционную проверку с реальной PostgreSQL, работающим Telegram и сервисом синтеза речи.

## Ограничения

- Автооценка **не является семантической проверкой**: синонимы и альтернативные корректные переводы могут получить 0 баллов.
- Качество эталонных переводов зависит от источника; ошибки исходного корпуса возможны.
- Сайт и Telegram используют общую БД, но аккаунты пока не связываются автоматически.
- Сервис башкирской озвучки дополнительный и требует отдельного запуска.
- Перед публичным развёртыванием нужны HTTPS, ограничения запросов, резервное копирование, проверка прав на исходные материалы и политика обработки персональных данных.
